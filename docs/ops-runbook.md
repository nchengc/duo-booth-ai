# 运营 Runbook(每日执行手册)

> 配套:`AGENTS.md`(规则与授权表)、`docs/decisions.md`(决策记录)、`DEPLOY.md`(部署清单)
> 来源:对标站 AI 精细化运营复盘的 5 张模板,已适配本项目

---

## 1. 每日检查(可设成定时任务 / AI 直接执行)

```
看一下今天的数据:
1. 付款单数和金额(扣除退款),和昨天同时段比。
2. 漏斗哪一步掉得最多,按设备和来源拆开(管理 API /api/admin/funnel?by=device|source;只算真实访客)。
3. PVUV.ai(接入后):各落地页的真实访客、首页和热门页的网页速度有没有变差、
   有没有新的 AI 助手来源或 AI 爬虫在读我们的页。
4. 每个实验:各版本曝光人数、每人收入、是否已够判定;
   曝光人数和 PVUV.ai 的 exposure 对一下,差太多先查统计代码。
5. 未处理的工单、渲染失败数(/api/admin/snapshot)、供应商余额。
6. 上周上线的改动,决策记录里"之后"一栏该补的补上。
用中文简短汇报,只说变化和要我决定的事。
```

## 2. 付款报警排查手册(报警触发时 AI 按此执行)

触发条件(见 `/api/admin/snapshot`):最近 6h 付款 vs 过去 7 天同时段均值,泊松 P(X≤k) < 2% 且同时段均值 ≥ 4 单。

排查顺序:
1. **漏斗哪一步丢了人**:`/api/admin/funnel?days=1` 对比 `days=8`,找断崖。
2. **对改动**:翻 `docs/decisions.md` 与实验变更,报警窗口内有没有上线。
3. **测试账号真实走一遍**:上传 → 生成 → 付款(测试模式)。
4. **是自己的改动 → 直接回滚,再汇报**;对不上就不动,继续监控。
5. 局限:单量太小(6h 均值 < 4 单)时不响,拉长窗口。

## 3. 实验层定义模板(新增实验时填这个)

```json
{
  "key": "paywall",
  "title": "付款框主推哪个套餐",
  "windowHours": 48,
  "minExposures": 400,
  "autoTune": false,
  "floor": 0.1,
  "arms": [
    { "key": "baseline", "content": {} },
    { "key": "plan-first", "content": { "featured": "basic_monthly" } }
  ]
}
```

通过 `POST /api/admin/experiments`(x-admin-key)写入。规则:
- 判定指标 = 曝光后 windowHours 内访客付款(扣手续费) ÷ 曝光人数
- 任何版本不给 100% 流量,原版至少留 10%
- 统计窗口从实验开始算,最多 120 天
- 价格类实验:`resolvePrice()` 服务器强制,付款时再核一遍

## 5. 趋势页 SOP(新热点 7 天流水线)

| 天 | 动作 |
|---|---|
| D0 | Google Trends / TikTok 发现 Breakout 词;确认与产品相关("热点都要围绕 ai rap") |

## 6. 客服政策(工单处理规则)

1. AI 处理前先查:付了什么/何时付/生成几次/余额/有无重复扣费
2. 政策内:每天最多自主全退 1 笔;第 2 笔问老板
3. 政策外直接婉拒:说清订阅已取消、不会再扣费、视频仍可下载
4. 同一类问题出现第二次 → 去改产品(例:加"歌曲是 AI 原创"提示)
